# Mika AI Dev Integration

For an existing-repository Studio engagement:

1. read the mapped `agent_entry` and Handoff Map;
2. read `start_here` and `mission`;
3. follow mapped canonical current-state, product, feature, architecture, operations, quality, decision, and governance roles;
4. validate packet hash and repository/deployment freshness;
5. treat generated narratives as evidence indexes;
6. then challenge the product, repair the harness, and plan execution.

Project Intake is integrated into Studio. Preserve packet owner decisions and stable non-negotiables without asking the owner to repeat repository facts. Convert only remaining delegable gaps to `STUDIO_DECIDES`.

Product uses feature dispositions as a starting constraint. Engineering preserves mapped continuity/invariants or records and validates replacements. Verification targets unverified claims and known risks. Red Team independently checks baseline, evidence, and runtime.

After material changes, update canonical truth and invalidate or refresh stale packet/handoff evidence. Do not maintain a generated shadow documentation system beside current canonical records.
