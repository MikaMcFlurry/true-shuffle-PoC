# Platform Routing

Read current official ecosystem evidence before a material stack change. Evaluate existing assets, target experience, native integrations, performance, distribution, operations, testing and the agent's ability to run the actual target.

- Native mobile when platform UX/APIs/background behavior/performance dominate.
- Cross-platform mobile when shared-product leverage outweighs native specialization and required integrations remain verifiable.
- Web/PWA for browser reach with deliberate accessibility, responsive input, caching/offline and real-browser constraints.
- Backend/data from consistency, query, scale, security and operational needs; avoid service sprawl without independent ownership/scaling justification.
- Desktop from OS integration, performance, update/distribution and reuse needs.
- Games from engine/runtime, rendering, physics, asset pipeline, target devices, netcode and runtime verification—not app-stack familiarity.
- AI systems should define evals, untrusted-context/tool boundaries, privacy, cost/latency, failure/fallback behavior and provider portability where it pays.

Preserve a stable working stack unless replacement materially improves the product or delivery system. Record migration and rollback consequences.
