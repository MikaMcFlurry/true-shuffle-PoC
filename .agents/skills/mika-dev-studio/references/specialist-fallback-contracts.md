# Specialist Fallback Contracts

Use only when the named specialist is unavailable as a separate Skill/context. Disclose role combination.

## Product fallback

Return: underlying goal/users; stable non-negotiables; one direction verdict; material `KEEP/IMPROVE/REDESIGN/REMOVE/ADD/PIVOT` decisions; coherent scope/exclusions; critical journeys/degraded states; measurable criteria; assumptions/risks. Use current dimension-specific benchmarks only when they improve a decision.

## Engineering fallback

Return: truthful baseline; product criteria and stable requirement IDs used; architecture/contracts; changed surfaces; exact setup/run/verify commands; requirement-ID-to-surface/test mapping; integration state; migrations/recovery; diagnostics; evidence run; known risks and remaining work.

## Verification fallback

Select project-relevant gates, run direct evidence, bind it to the exact subject, snapshot/map all non-negotiables, and validate Evidence Ledger 1.2. Report `PASS/FAIL/NOT_RUN/NOT_APPLICABLE` without converting unknowns into readiness.

## Repository grounding fallback

If Repository Intelligence is unavailable, Studio may perform proportional read-only grounding but may not fabricate a V2 packet or claim `ALIGNED`. If Repository Handoff is unavailable, continue from existing canonical project truth; do not create an unvalidated parallel control plane.

## Non-fungible review

No local fallback can manufacture `FRESH` independence. A material positive release claim remains blocked until a separate eligible reviewer reproduces critical evidence and returns a compatible verdict.
